UX Patterns & Interactions

Five additions to the design system that improve usability without breaking the gym aesthetic. All patterns respect prefers-reduced-motion and are keyboard-accessible.

1. Persistent Alert Notifications

Critical alerts (clearance needed, lock engaged, system issues) appear as inline banners that live on the page until actively dismissed. Not dismissible toasts. Applies Law 7: refusal is a stamp, not an error toast. Athletes and coaches see them; they don't disappear if you blink.

Example: Coach Review Queue with an incoming alert
⚠
Layer 11 Lock Engaged
Marcus D. has been flagged by the safety gate. Return-to-training clearance requires head-coach review.
Review clearance request
⚡
Incoming Data
New session data arrived from the floor kiosk. Queue contains 3 pending reviews.
✓
Sync Complete
All changes saved to the continuity ledger. Last sync: 2026-08-01 18:34 EDT.
ℹ
Network Unavailable
The floor kiosk has no connection. Do not close this screen — a check-in submitted now is not saved.

Usage: Use .alert with .alert--critical, .alert--warning, .alert--success, or .alert--info. Place at top of content area or inline near related content. Keyboard-accessible; screen readers announce presence.

⚠
Write only what is true
The network alert above used to read “changes will sync when connectivity returns.” There is no offline write queue in the platform — no service worker, no navigator.onLine handling, no pending-write store. A check-in submitted during an outage is lost. Reassuring copy over silent data loss is worse than no copy at all, so the alert now tells the athlete not to close the screen. Restore the softer wording only once a queue actually exists.

2. Form Undo/Redo Levers

Athletes and coaches make mistakes on the kiosk; admins make data-entry errors. Undo/redo buttons styled as physical levers sit near form controls. Click to roll back to the last saved state. Solves the "oops I submitted the wrong RPE" problem without complex recovery flows.

Example: Athlete kiosk form with undo control

Usage: Wrap in .undo-redo-group. Use .btn--lever for individual buttons. Connected to form state; rolls back to last saved checkpoint, not every keystroke.

3. Empty State Guidance

When a list, grid, or panel loads with no data, show what's supposed to go there and what's needed to make it appear. Encourages exploration and explains the flow. Much better than blank space.

Example: Coach Review Queue with no pending reviews
📋
No Pending Reviews
All athletes on the floor have been cleared. New reviews will appear here when the Layer 10 system flags a check-in.
🏃
No Athletes Checked In
The kiosk is waiting for someone to scan a card or enter a PIN. Invite athletes to the floor or check the schedule.

Usage: Use .empty container with .empty-glyph, .empty-title, .empty-msg, and .empty-action. Pair with relevant contextual actions.

4. Command Reference Card

A command cheat that pops up on ?, styled as a laminated notice posted on the gym wall. It renders from a shortcut registry (shortcuts.ts), not from hand-written markup, so it can only list keys that something actually binds — see the note below for why that matters.

⚠
This card used to be a picture of a feature
The first version listed eight shortcuts — submit/next, approve/deny, lock/unlock — and not one of them was bound to anything. That is worse than shipping no card, because a documented key that does nothing teaches a user the keyboard is not worth trying here. The overlay now renders from the registry, and a test asserts every listed entry has an owning component.

Approve/deny are deliberately absent. The coach's review queue (shadow/review-projection) is read-only, and the only coach decision endpoint (coach-reviews) resolves session_id to a training session while the queue holds intake_case_id — a different entity. Binding a key to approve would fail validation or, on an ID collision, attach a review to the wrong athlete. Triage needs a coach-facing write endpoint first.
Example: Floating command card in a workspace
Keyboard Everything here is bound. Nothing here is decoration.
Anywhere
  • ⌘K Open the card catalog — jump to any surface
  • / Open the card catalog (when not typing in a field)
  • ? Show this list of shortcuts
In a dialog
  • Esc Close the catalog, the corridor, or this list
In a list
  • ↑ ↓ Move through catalog results
  • ↵ Open the highlighted result
esc or ? to close
⌨
Press ? to show commands

Usage: Use .commands as a floating or drawer component. Contains .commands-list with .commands-item pairs of .commands-key and .commands-desc. Show on ? keypress or in an always-visible corner.

5. Print Parity & Paper Rendering

Every screen prints identically to how it renders on screen. A board governance record and a family record are the same stamped sheet — print them and they should look the same. Print this page to see how the room-specific materials (plank wall, desk lamps) disappear and content reorganizes for paper.

Print behaviors per room
All rooms on print:
  • Remove decorative room backgrounds (plank wall, brick wall, cork wall, etc.)
  • Remove light fixtures and shadow effects
  • Print on white background with black text
  • Remove navigation rails, toolbars, and interactive chrome
  • Keep all data visible and legible
  • Preserve stamps and badges (printed as outlined boxes)
  • Convert links and buttons to text with lines (line-through or underline)
Room-specific print tweaks:
  • .room--office – Ledger tape becomes columnar, plank background disappears
  • .room--floor – Kiosk bar and schedule components scale down for 5x8 card stock
  • .room--board – Role rail becomes a header; board seat names remain visible
  • .room--clinic – Medical clearance stamps remain prominent; green shade disappears
  • .room--file – Cork wall and gooseneck disappear; research data stays centered
  • .room--night – Ink ground becomes white; locked/refusal data remains legible
✓ Test the print view
Right-click → Print, or Cmd+P (Mac) / Ctrl+P (Windows). The design system renders correctly; the real app pages (board, kiosk, admin console) will do the same once their @media print sections are tuned per room.

Usage: Add room-specific @media print { } rules. Reference ppbf.css for the base media query structure. Each room should document what appears on paper.

All five patterns are zero-asset, keyboard-accessible, and respect prefers-reduced-motion. Integrate by adding the class names to your markup and handling the interactions in your application layer.
