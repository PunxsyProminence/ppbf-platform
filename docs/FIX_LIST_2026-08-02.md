## Part 1 — Confirmed defects, in fix order

### P0 — a shipped feature does not work at all

**1. The drill library renders empty forever.** `apps/web/app/coach/drills/page.tsx:53`

`GET /api/pilot/drills` responds `{ ok, organization_id, items }`. Both client consumers
destructure `payload.drills`, which does not exist. The coach drill library — shipped in
#161 and live in production now — shows nothing and always will.

Route tests pass. Component tests pass. Nothing tested the contract between them, which is
the only place the bug lives. Fix the key, then add a test that asserts the client reads
what the route actually returns.

**2. `platform_owner` can null any child's PIN, deactivate the account, and revoke every
session — in any gym.** `apps/web/app/api/pilot/platform/users/create/route.ts:20`

Guard is `requireRole(principal, ['platform_owner'])` and `organization_id` comes from the
**request body**, not the session. Line 47 calls `createOrUpdateAthleteAccount`, which is an
upsert: re-running it against an existing athlete nulls `pin_hash`, and the surrounding
handler can deactivate and revoke.

This is the boundary that was supposedly closed. `athlete-pin-directory` and
`athlete-accounts` were narrowed to `organization_admin` with a comment about Omega not
holding the keys to a child's account. This route does the same thing and was missed.

**3. `pilot.auth_rate_limit_buckets` is created by DDL issued from an unauthenticated login
request.** `apps/web/src/server/pilot/rateLimit.ts:72`

`ensureDurableRateLimitTable()` runs `create table if not exists` from inside a request
handler on the login path. No file in `infra/azure/` creates this table and no
`pilot:apply-*` runner asserts it, so a database built the sanctioned way does not have it
until an anonymous request creates it.

This is the shape of #111 — "an anonymous request could execute DDL against production
Postgres" — surviving in the auth path. Write the migration, wire it into all three
`apply-migrations.yml` lists, and delete the runtime DDL.

### P1 — child-safety and safeguarding surfaces

**4. The `Tell Us` trigger is 28.5px.** `apps/web/components/FeedbackBox.tsx:99`

The disclosure box is how a child reports harm, and this is the only control that opens it.
It is mounted in the sticky header on every authenticated route via
`GlobalRoleHeader.tsx:83`, including for athletes.

#166 edited this exact file, raised the two buttons *inside* the panel to 44px, and left the
one that opens it untouched — while its commit message claims "All 56 are at 44px now" and
"every interactive target."

The verifier corrected two things worth keeping: at ~74x28.5 it **passes** WCAG 2.2 AA
(24x24) and fails AAA (44x44), so this is a breach of the project's own committed floor
rather than of AA — medium, not high. And the real gap is bigger than 44-28.5: every sibling
control on that bar uses the shared `CONTROL` constant at `min-h-[var(--tap)]` = **55px**.
The trigger is 26.5px shorter than everything beside it, and still on the legacy alias
palette rather than the design-system tokens #155 moved the bar onto.

**5. An in-flight scan can overwrite a human's `block` and erase the attestation.**
`apps/web/src/server/pilot/videoSessions.ts:197`

A `block` decision leaves `status='quarantined'`, moves `scan_state` to `blocked`, and clears
`scan_claimed_at` — while a worker may still be mid-scan. `settleVideoSessionScan`'s guard is
`where video_session_id = $1 and status = 'quarantined'`, with no `scan_state` predicate, so
the returning sweep can promote to `ready` the exact video an administrator just refused.

The invariant this platform holds is that a human resolves what the scan could not, and never
overturns what it refused. This is the machine overturning the human.

**6. The admin safeguarding banner promises the child a conversation the acknowledgement no
longer makes.** `apps/web/app/admin/feedback/page.tsx:253`

#161 deliberately removed the promise of a conversation from what a child sees —
`feedbackAcknowledgement()` now returns exactly *"Thank you for telling us. A person at the
gym reads this."* The admin-side banner still tells the responder the child was promised one.
The responder acts on a false belief about what the child expects.

**7. Withheld safeguarding bodies render as a blank card, and the only covering test uses a
payload the server cannot emit.** `apps/web/app/admin/feedback/page.tsx:96`

The withholding is correct — `PLATFORM_FEEDBACK_SQL` nulls the body of every safeguarding
row. The surface on the other end shows an empty card with no explanation of *why* it is
empty, and its test constructs a row the server would never produce, so the real rendering
path is uncovered.

**8. #150's administrator path for `blocked` video has no caller.**
`apps/web/app/coach/video-analysis/page.tsx:292`

`POST /api/pilot/video/scan-review` exists and works. Nothing in the client calls it. The only
control an organization_admin can reach is the Release button, which 409s and tells them to
ask an administrator — which is them.

**Note a genuine disagreement:** a second finder raised this same gap from the react-runtime
angle and the verifier **refuted** it, arguing a path does exist. Two agents reached opposite
conclusions on the same question. Resolve this by hand before building anything.

### P2 — accessibility floor did not land

**9. #166's sweep only rewrote literal `min-h-[Npx]`. 18 controls on Tailwind's numeric
scale are still 32-40px.** `apps/web/app/coach/decision-loop/page.tsx:474`

Every sizing edit in #166 was a textual substitution on `min-h-[<n>px]`. Controls sized
`h-8`/`h-9`/`h-10` were invisible to it — and those are `height`, not `min-height`, so
padding cannot rescue them. Affected: `/coach/decision-loop` Accept/Reject/Load Outcomes;
eleven controls on `/admin/shadow` (Open, Mark Clean, Quarantine, Resolve, Reject, Save);
two capability toggles on `/admin`; the donation status select in `RevenueFundingCenter`.

The verifier found an **18th the audit missed, and the worst one**: `AthleteWorkspace.tsx:1425`
is a session-duration number input at `h-9` = 36px on a **child-facing** surface, where #166's
own rule reserves 55px.

**10. ~110 buttons and links carry no height constraint at all and compute 22-38px.**
`apps/web/components/AthleteWorkspace.tsx:1528`

Including the athlete floor **Check In / Check Out**. Nothing in #151, #155 or #166
established a default floor: `ppbf.css` sets `min-height` only on `.btn` (44px) and
`.btn--kiosk`/`.input--kiosk`/`.tag` (55px), and roughly 61 pages mostly do not use those
classes. Every control styled with bare padding lands wherever its font size leaves it.

The real fix is a default floor in the design system, not another sweep. Three sweeps have
now each missed a different subset.

**11. `--text-4xl` is 50px while Tailwind's `--text-5xl` is 48px.** `apps/web/app/globals.css:98`

The alias block is unlayered so it beats Tailwind's `@layer theme` unconditionally. Every
`text-4xl md:text-5xl` heading **shrinks** when the viewport gets wider.

### P3 — correctness and discoverability

**12. An athlete's drill due date renders one day early.**
`apps/web/app/athlete/progression-intelligence/page.tsx:304`

`pilot.drill_assignments.due_date` is a pg DATE. `db.ts` correctly registers
`setTypeParser(1082, identity)` so the API returns `"2026-08-15"` verbatim — and then the
page puts that string through `new Date().toLocaleDateString()`, which parses it as UTC
midnight and renders the previous day in every timezone west of Greenwich. The server-side
fix is in place; this consumer undoes it.

**13. Three consoles from #161 are reachable only by typing the URL.**
`apps/web/app/admin/page.tsx:862`

`/admin/athletes` (correct an athlete record, deactivate a departing athlete),
`/admin/export` (the roster takeout that hands a family their own information back), and
`/coach/drills`. No navigation anywhere in the app links to any of them. The backup and
export built for floor readiness cannot be found by the people who need them.
