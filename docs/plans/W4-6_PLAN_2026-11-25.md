## 4. How it works (proposed; the open choices are section 7's questions)

- **Who is listed (SC-1).** For a coach or gym admin with an active staff membership in the gym: each live athlete of the gym who is an active member (Q3), was present at least once (Q2), and whose last present day is at least the gym's number of days ago. "Last present day" is the later of (a) the register's last present day and (b) the gym-local day of their last standing session mark (Q6.3 A). Read from two separate queries and combined in the module, on this page only: `pilot.attendance_reconciled`, `getAttendanceLast28Days` and every attendance figure are not changed (Q6.3 A; CT-13).
- **The boundary (INFERRED from "no present mark for the gym's number of days").** With a gap of N days and today T, an athlete is listed when T minus the last present day is N or more: no present mark on any of the last N gym days, today included.
- **What a row shows:** name (opens the athlete's Passbook), last present day, days since. Nothing else: no age, no date of birth, no membership or payment field, no count. No new warning, gate or disclaimer (L1).
- **The setting (SC-0a).** `pilot.organization_stopped_coming_policy`: one row per gym, `gap_days` with a CHECK of the allowed values (Q1), `set_by_account_id`, `set_at`. No row means 14 days. The allowed list lives in the server module and the GET returns it as `choices` (as the tablet route does), so no new shared file and no edit to `scripts/ci-classify-paths.mjs` is needed (the module is under `apps/web/src/server/pilot/`, which that script already covers).
- **The mark (SC-3a).** `pilot.athlete_reached_out_marks`, shaped on rest marks (Q4): who and when, no text; one current mark per athlete; clearing keeps the row; every change audited (`shadow_mirror: false`); a schema-ownership test pins the column list; the table joins `PUBLIC_SURFACE_FORBIDDEN_TABLES`. The page shows "Reached out by (name) on (date)" only while the mark is newer than the athlete's last present day, so an athlete who came back and stopped again starts clean.
- **Where SC-1's code lives:** a new `src/server/pilot/stoppedComing.ts`. Not in `attendancePrecedence.ts` (its test requires that module to read only the view) and not in `sessionRunAthletes.ts` (W4-7's "Here" tap retries may touch it; INFERRED from the brief's item list, not checked).
