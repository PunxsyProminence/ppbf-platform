## The defect

Tailwind v4 emits `@layer theme, base, components, utilities;` and puts every
utility inside `@layer utilities`. `ppbf.css` declares no layer at all, and
`globals.css` layers only two `@layer base` blocks. Layer order is resolved
*before* specificity, and unlayered beats layered, so a single-class ppbf
selector defeats any utility naming the same property regardless of how the
selectors compare. The utility still reads as correct in the JSX.

## The three seed examples, re-checked

This scan was commissioned off three instances found by eye. Two of them no
longer exist on `main`, which matters: the *class* is alive, the *examples* are
not, and a reader who greps for them and finds nothing should not conclude the
defect was imagined.

- **`.stamp` vs `absolute` on the sign-in board.** Not present. The whole styled
  board was reverted in #520 (`5e94aae6`), which deleted the
  `stamp ... absolute -bottom-[18px] right-[24px]` span. That commit message
  states the mechanism in full, so it is where the defect was first written down.
- **`.btn--lever` vs `min-h-[44px]` on `/parent/consent`.** Fixed in #525
  (`a11ea7c1`), the tip of `main` this scan runs against; the button is now
  `.btn .btn--kiosk` and the page carries a comment explaining why. But the
  pattern it was an instance of is still live at **25 other call sites**, all
  listed under BROKEN below - `/parent/consent` was fixed, the defect was not.
- **`.room` vs `bg-[var(--hide-950)]` on `<main>`.** Still live at 84 sites.
  `RoleStandaloneView` drops the utility on its room branch and says so in a
  comment, but the pages that paint a room directly still carry it. Filed DEAD,
  not BROKEN: the room's ground is the intended one.

## How the edge cases were treated

- **Token meaning is not guessed.** Every distinct token found in the source is
  handed to the installed Tailwind v4 compiler running over the real
  `globals.css`, and whatever comes back out of `@layer utilities` is what that
  token does. That is how `space-y-6` is correctly excluded (its real selector
  is `.space-y-6 > :not(:last-child)`, so it never touches the element itself),
  how `border-l-4` is known to set `border-left-style` as well as the width, and
  how project classes such as `badge--filed` are known not to be utilities.
- **Breakpoint prefixes.** `sm:min-h-[...]` compiles to
  `@media (width >= 40rem) { min-height: ... }`. The ppbf rule is unlayered at
  *every* width, so the prefixed utility is defeated inside its own breakpoint
  too. It is counted, and each entry states the width it was supposed to take
  effect at. A prefixed utility is a strictly narrower loss than an unprefixed
  one, which is why the scope is printed rather than merged away.
- **State prefixes.** `hover:` / `focus-visible:` / `disabled:` compile to real
  pseudo-class selectors, and matching is done on those. An *unconditional* ppbf
  rule defeats a `hover:` utility (the hover style never appears, at any moment),
  so that counts. A ppbf `:hover` rule is **not** counted against an unprefixed
  utility: the utility still renders at rest and only yields during hover, which
  is usually the intent.
- **Shorthands, both sides.** `padding: 0 var(--s4)` is expanded to four
  longhands before comparison, so it registers against `px-[var(--s4)]`.
  Shorthands whose per-longhand value cannot be decomposed (`background:`,
  `transition:`, `font:`) collide on property name only and are filed DEAD, never
  BROKEN, because there is no evidence a specific value was lost.
- **Inline `style={{...}}`** on the same element outranks both sheets, so a
  property set there is excluded. It is not a layer casualty.
- **Ancestor-scoped ppbf rules** (`.mat-leather .stamp`) and rules needing a
  second class the element does not carry are not counted: they are not proven
  to apply at that call site.
- **`globals.css` is read as well as `ppbf.css`.** It `@import`s ppbf.css at its
  top, so it is later in source order and wins ties; a report naming only
  ppbf.css would attribute those overrides to the wrong file.
